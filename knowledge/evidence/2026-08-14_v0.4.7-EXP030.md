## Finding 1: Cylindrical Face Pattern Is Identical Across Models

### Evidence

All cylindrical faces (C04 vc=70, C05 vc=56, C11 vc=64) have identical token pattern:

| Model | vc | First 10 tokens |
|-------|-----|-----------------|
| C04 | 70 | `1, 0, 150, 0, 153, 0, 150, 0, 153, 0` |
| C05 | 56 | `1, 0, 150, 0, 153, 0, 150, 0, 153, 0` |
| C11 | 64 | `1, 0, 150, 0, 153, 0, 150, 0, 153, 0` |

**Verification**: Byte-identical first 110 tokens across all three models.

### Analysis

The alternating pattern (150, 153) is a structural signature of cylindrical faces. The pattern is:
- Token 0: 1 (ONE delimiter)
- Token 1: 0 (ZERO)
- Tokens 2+: Alternating 150, 0, 153, 0, ...

This pattern is independent of hole diameter (3mm, 4mm, 5mm all have same pattern).

### Conclusion

**Status: Verified**

The alternating pattern (150, 153) is a structural signature of cylindrical faces, not geometry-specific data.

## Finding 4: B1Len Formula Explained

### Evidence

The formula `b1Len = 2*(vc - secCount)` holds for all 41 faces.

**Derivation**:
- From INV-017: sectionBodyTokenCount = Block2[i] - 1 = loopSize - 1
- Parser calculates sectionLens as tokens between ONEs (including ONE delimiter)
- Actual relationship: `sum(sectionLens) = 2*vc - 3*secCount`
- And: `b1Len = sum(sectionLens) + secCount = 2*(vc - secCount)`

**Verification**: Verified across all 41 faces.

### Analysis

The formula is a structural invariant, not a geometry-dependent parameter.

### Conclusion

**Status: Verified**

The formula is a structural invariant.

## Finding 5: Token Values Are Not Vertex/Edge Indices

### Evidence

For cube face with 4 vertices:
- Tokens: `[1, 5, 82, 0, 79, 62]`
- Vertex indices: 0, 1, 2, 3
- Token values 5, 82, 79, 62 are OUT OF RANGE for 4 vertices

**Verification**: Token values exceed vertex count for all faces tested.

### Analysis

Tokens cannot be vertex indices because values exceed vertex count.

### Conclusion

**Status: Verified**

Tokens are NOT vertex indices.
